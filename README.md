# Jev 纸面交易台（BTC / ETH）

用 [Vercel AI Gateway](https://vercel.com/ai-gateway) 上的 `typesafe-ai/jev` 当决策引擎，
每 5 秒对 BTC / ETH 评估一次，画出买卖点与决策历史。

**纸面交易（paper trading）。不接交易所，不下真实订单，不碰任何资金。**
账户、持仓、成交、盈亏全部存在访问者自己的浏览器 `localStorage` 里。

---

## 先说清楚它不是什么

这一点比功能重要，写在最前面：

**Jev 是评估模型，不是价格预测模型。** 它的接口是「给你一段状态描述和判别标准，
判断这件事成立吗 / 属于哪一类」——它不会预测未来价格。

这个项目里它做的事是：**按写死的 criteria 给当前盘面分类**（买 / 卖 / 不动）。
这套信号有没有预测力，**未经任何回测验证**。目前能观察到的只是「盘面很平时它会说 hold，
置信度低」——这跟「它能赚钱」是两回事。

所以：

- ❌ 不是投资建议，不是能跑的策略
- ✅ 是一个能跑通的「模型即决策引擎」的完整骨架：真实行情 → 结构化状态 → 模型评估 → 执行 → 记账 → 可视化

---

## 回测结果（2026-09-20，真实历史行情）

上面说「未经验证」，那就去验证。用 `tools/backtest.js` 把**和线上完全同一套规则**跑到过去 7 天的真实行情上：

| 项 | 结果 |
|---|---|
| 样本 | 70 个时点 × 2 个标的 = **140 次 Jev 判断**，2026-09-14 → 09-20，小时粒度 |
| **Jev 说 buy** | **0 次** |
| Jev 说 sell | 13 次（BTC 6 / ETH 7） |
| Jev 说 hold | 127 次（**90.7%**） |
| 实际成交 | **0 笔**（没买过，自然也没得卖） |
| 策略收益 | 0.00%（全程空仓） |
| 买入持有基准 | **+2.76%** |
| 差额 | **-2.76 个百分点** |

**拆开看为什么一笔都没成交**（48 次判断的诊断样本）：

| 原因 | 占比 |
|---|---|
| Jev 自己说 hold | 88% |
| Jev 说 sell，但空仓没得卖 | 13% |
| 被风控闸门拦 | **0%**（marketRisk 中位 0.13、最大 0.34，压根没到 0.5） |
| 被概率阈值拦 | 0% |

**这个结果说明什么**

- 第一反应会是「模型不给买入信号」。**但下一节的对照实验推翻了这个解释。**
- 140 次判断、一周、单一行情区间 —— 样本量太小，任何结论都要打折。

## 三套 criteria 的对照实验

固定同一批样本、同一套交易规则，**只换 criteria 的措辞**，外加一个随机信号基线。

### 第一轮：7 天，35 个样本

| criteria | 思路 | buy | sell | hold | 成交 | 胜率 | 收益 |
|---|---|---|---|---|---|---|---|
| `strict` | 要求短+中周期同向才买 | **0** | 6 | 64 | 0 | — | +0.00% |
| `reversion` | 均值回归，跌买涨卖 | **0** | **0** | **70** | 0 | — | +0.00% |
| **`trend`** | 只看中周期方向，最宽松 | **29** | 28 | 13 | **10** | 60% | **+2.17%** |
| 随机基线 | 三选一，蒙特卡洛 200 次 | — | — | — | — | — | 中位 +0.40%（90% 区间 −2.08% ~ +2.06%） |
| 买入持有 | 起点均分两个标的拿到最后 | — | — | — | — | — | **+2.72%** |

这一轮只能说「**看不出来**」：+2.17% 落在随机的噪声区间里，但 10 笔成交根本不够下结论。所以扩到 90 天再跑一遍。

### 第二轮：90 天，89 个样本（2026-06-23 → 09-20）

```bash
node tools/compare-criteria.js --days 90 --samples 89 --step 24
```

| criteria | buy | sell | hold | 成交 | 胜率 | 收益 |
|---|---|---|---|---|---|---|
| `strict` | **0** | 14 | 164 | 0 | — | +0.00% |
| `reversion` | **0** | **0** | **178** | 0 | — | +0.00% |
| **`trend`** | **77** | 50 | 51 | **52**（买 27 / 卖 25） | **48%** | **+12.40%** |
| 随机基线 | — | — | — | — | — | 中位 **+12.75%**（90% 区间 +2.82% ~ +21.44%） |
| 买入持有 | — | — | — | — | — | **+41.71%** |

样本量够了之后，结论从「看不出来」变成了「**没有 edge**」，而且是两个独立的坏消息：

**1 · 和随机信号无法区分。** `trend` 跑出 +12.40%，随机乱按的中位数是 **+12.75%**——**比它还高一点**。52 笔成交的胜率 **48%**，低于抛硬币。这一轮成交数够多了，不再是样本量问题。

**2 · 大幅跑输「什么都不做」。** 这 90 天是一轮强上涨（买入持有 **+41.71%**）。`trend` 只拿到 +12.40%，**差 29.3 个百分点**——52 笔进进出出，手续费 + 踏空 + 48% 的胜率，把涨幅磨掉了七成。**在一个单边上涨的行情里，趋势跟随策略输给躺平，这是很说明问题的。**

**两个窗口一致的部分**：`strict` 和 `reversion` 在 7 天和 90 天里**一次 buy 都没说过**。所以「是措辞问题，不是模型不会说 buy」这个判断成立——我第一轮回测后推断的「模型本身几乎不输出 buy」**是错的**。

**仍然要打折的地方**：90 天仍然只是一个区间、一种行情（强上涨）。没有熊市和震荡样本，就不能说「Jev 在任何行情下都没 edge」。只能说：**在当前这套配置下，没有找到任何支持它有 edge 的证据，反而有两条证据指向相反方向。**

所以线上默认切到 `trend`（唯一会真的产生成交、能让买卖点功能显示出来的那套），但页面和这份 README 都把上面这些数字摆在明处。**不要看到「有成交」就以为策略有效。**

**自己跑**：

```bash
export AI_GATEWAY_API_KEY=vck_xxx
node tools/compare-criteria.js --days 90 --samples 89 --step 24       # 90 天三套对照，约 15 分钟
node tools/compare-criteria.js --samples 36 --days 7                  # 7 天三套对照，约 6 分钟
node tools/backtest.js --days 7 --samples 70 --step 2                 # 单套回测，约 3.5 分钟
node tools/test-strategy.js                                           # 交易规则单元测试，35 项，秒级
```

限流 30 次/60 秒，脚本默认 2.6 秒间隔 ≈ 23 次/分；实际扣费 $0。

### 数据源与保真度

回测喂给模型的状态必须和线上一致，否则测的是另一套东西。这里有个坑：

| 数据源 | 粒度 | 能算出哪些动量 |
|---|---|---|
| CoinGecko（默认） | 区间越长越粗：`days=1` → 5 分钟；`days=90` → **1 小时** | 90 天时只有 24h / 1h，5m / 1m 只能是 null |
| Coinbase（`--source coinbase`） | **恒定 5 分钟**，免 key，翻页拼接 | 24h / 1h / 5m 都是真值，1m 仍为 null |

线上每拍给模型的是四个动量，但 90 天那轮只喂了两个。**宁可让模型知道「这个没有」（给 null），也不拿 1 小时的变化冒充 5 分钟**——早期版本就是这么错的，已修。

```bash
node tools/compare-criteria.js --source coinbase --days 90 --samples 89 --step 288 --variant trend
# step 288 = 每 288 根 5 分钟 K 线取一个样本（约每天一个）
```

### 保真度验证：补上 5 分钟动量后，结论变了吗？

用真实 5 分钟 K 线重跑 `trend`，同一区间、同样 89 个样本：

| | 小时粒度（只有 24h / 1h） | **5 分钟粒度（含真实 5m）** |
|---|---|---|
| buy / sell / hold | 77 / 50 / 51 | 66 / 58 / 54 |
| 成交 | 52 | 50 |
| **胜率** | 48% | **25%** |
| 收益 | +12.40% | **+17.19%** |
| 随机基线中位 | +12.75% | +13.04% |
| 随机 90% 区间 | +2.82% ~ +21.44% | +2.89% ~ +23.50% |
| 买入持有 | +41.71% | +42.46% |

**收益数字变了，结论没有变。**

- 补上 5m 之后收益从 +12.40% 升到 +17.19%，**第一次站到了随机中位数之上**。但 +17.19% 仍然稳稳落在随机的 90% 区间（上界 +23.50%）**之内**——依然是噪声。
- 更该注意的是**胜率从 48% 掉到 25%**：收益变高而胜率腰斩，说明这轮收益靠的是少数几笔大赢，不是判断更准。这是「运气」的典型形状，不是「edge」的形状。
- 两条路都**大幅跑输买入持有**（−25.3 个百分点）。

所以「当前配置下没有 edge」这个结论，**对特征集是稳健的**——换一套更完整的数据喂给模型，还是同样的结论。

### 第三轮：熊市窗口（2022-01-01 → 07-01，BTC 4.6 万 → 1.9 万）

上面两轮都是上涨行情。唯一没检验的维度是下跌，所以补一轮：

```bash
node tools/compare-criteria.js --from 2022-01-01 --to 2022-07-01 --gran 5 --samples 90 --step 576
```

| criteria | buy | sell | hold | 成交 | 胜率 | 收益 |
|---|---|---|---|---|---|---|
| `strict` | 7 | 64 | 109 | 8 | 25% | **−0.71%** |
| `reversion` | 20 | **0** | 160 | 2 | — | **−36.82%** |
| **`trend`** | 62 | 98 | 20 | **60** | 50% | **−12.60%** |
| 随机基线 | — | — | — | — | — | 中位 −31.68%（90% 区间 −45.24% ~ −17.30%） |
| 买入持有 | — | — | — | — | — | **−64.85%** |

和牛市完全不是一回事：

- **三套全部跑赢买入持有。** 因为策略只能「空仓或做多」——下跌行情里 sell 信号让它待在现金里，不亏就是赚。
- **`trend` 的 −12.60% 优于随机 90 分位（−17.30%）**，这是三轮里**第一次落在噪声区间外**。
- **`reversion` 被重创 −36.82%**：20 次 buy、**0 次 sell**。它按设计就是「跌买涨卖」，在持续下跌里等于一路接刀。
- **`strict` 反而最好（−0.71%，只成交 8 笔）**：它在牛市两轮里一次 buy 都没说过，在熊市里倒是说了 7 次。**criteria 触发不触发，高度依赖行情状态本身。**

### 但这是模型的功劳吗？——机械规则基线

熊市那轮 `trend` 跑赢随机 90 分位，很容易被读成「模型有价值」。可是有个很自然的质疑：**单边下跌里，任何「趋势不好就空仓」的规则都能做到，跟 Jev 有什么关系？**

于是加了一组**不调模型、只用一行 if** 的机械基线（`tools/naive-baseline.js`，零 API 调用），同一批样本、同一套交易规则：

**牛市窗口（2026-06-23 → 09-20）**

| 规则 | 成交 | 收益 |
|---|---|---|
| 涨就买跌就卖（1h 且 24h 同向） | 52 | **+28.87%** |
| **Jev `trend`** | 60 | **+17.19%** |
| 只看 1h | 92 | +15.82% |
| 只看 24h | 102 | +10.23% |
| 反向（跌买） | 104 | +7.59% |
| 一直空仓 | 0 | 0.00% |
| 随机基线（200 次） | — | 中位 +13.69%（90% +4.85% ~ +22.97%） |
| 买入持有 | — | **+43.81%** |

**熊市窗口（2022-01-01 → 07-01）**

| 规则 | 成交 | 收益 |
|---|---|---|
| 只看 24h（涨买跌卖） | 82 | **+4.19%** |
| 涨就买跌就卖 | 52 | −3.65% |
| **一直空仓** | 0 | **0.00%** |
| **Jev `trend`** | 60 | **−12.60%** |
| 只看 1h | 88 | −25.79% |
| 反向（跌买） | 80 | −55.92% |
| 随机基线（200 次） | — | 中位 −32.95%（90% −44.11% ~ −19.14%） |
| 买入持有 | — | **−64.85%** |

**这张表把问题回答得很干脆：**

- 两个窗口里**都至少有一条一行 if 的规则跑赢 Jev**。
- 熊市里 **「什么都不做」（0.00%）就跑赢了 Jev 的 −12.60%**。
- 所以 `trend` 在熊市「跑赢随机 90 分位」**不是模型的判断力**，而是**空仓本身在下跌行情里就值钱**——而这不需要模型。
- 反过来，牛市里最好的机械规则（+28.87%）也没跑赢买入持有（+43.81%）。

**合并两个窗口看一个完整来回**（大涨 + 大跌；注意这是两段不同年份的行情拼起来，只作参考）：

| | 牛市 | 熊市 | 合计 |
|---|---|---|---|
| Jev `trend` | +17.19% | −12.60% | **+2.42%** |
| 一直空仓 | 0% | 0% | **0.00%** |
| 随机基线中位 | +13.69% | −32.95% | −23.77% |
| 买入持有 | +43.81% | −64.85% | −49.46% |

**一个来回下来，Jev 用 112 笔交易换来 +2.42%，跟躺着不动（0%）几乎没差别。** 它跑赢买入持有，只是因为这段时期整体是亏的。

### 最后一个保真度修复：Jev 得知道自己持仓

前面所有对照实验里都有个缺陷：`buildState(snap, {})` —— 状态是预计算的，**持仓永远传空**，等于 Jev 全程不知道自己已经买了。而线上每拍都把真实持仓传给它。这一点很要紧，因为 `sell` 的 criteria 原文就写着「**已有持仓**且出现见顶迹象，应减仓或离场」。

修成「边问边跑」（每拍用当前真实持仓构造 state）后重跑牛市 `trend`：

| | 持仓不可见（旧） | **持仓可见（修复后）** |
|---|---|---|
| buy / sell / hold | 66 / 58 / 54 | 64 / 52 / 60 |
| 成交 | 50 | 50 |
| 胜率 | 25% | 25% |
| 收益 | +17.19% | **+16.71%** |
| 随机基线中位 | +13.04% | +12.66% |
| 随机 90% 区间 | +2.89% ~ +23.50% | +3.51% ~ +23.53% |
| 买入持有 | +42.46% | +43.81% |

**差 0.48 个百分点，胜率一模一样。** 所以结论对这个缺陷也是稳健的——不过这是个真 bug，已修。它提醒的是：**回测里「模型看到的信息」必须和线上一字不差，否则测的就不是同一个东西。**

## 架构

```
浏览器 (assets/app.js)          服务端 (Vercel Serverless)
┌────────────────────┐          ┌──────────────────────────┐
│ 每 5 秒 tick       │  GET     │ api/tick.js              │
│ 账户 / 持仓 / 历史  │ ───────► │  1. CoinGecko 取行情      │
│ localStorage 持久化 │  /api/   │  2. 组装 state            │
│ 执行买卖 / 记账     │  tick    │  3. 问 Jev（1 请求 3 问） │
│ 画图 / 渲染         │ ◄─────── │  4. 返回决策              │
└────────────────────┘          └──────────────────────────┘
```

**为什么账户放前端**：Serverless 是短暂的，写内存会丢，接数据库又超出「基础网站」的范围。
前端 localStorage 反而成了最可靠的权威账本——刷新不丢，清空可控。

**为什么每拍只发 1 个 Jev 请求**：BTC、ETH、风控三个问题打包在同一个请求里。
Jev 实测限流 **30 次 / 60 秒**，5 秒一拍 = 12 次/分钟，留在限内。

**为什么访问人数不会放大调用量**：`api/tick.js` 做了两层收敛——

1. **新鲜期缓存**：结果按持仓签名缓存 5 秒，期内直接复用
2. **并发合并**：同时到达的请求 `await` 同一个 in-flight Promise

实测 4 个并发请求只触发 1 次 Jev 调用。所以不管多少人同时打开，Jev 调用恒定 ≈12 次/分钟。

## Jev 的输入

每一拍真正发出去的状态（`state`）长这样：

```
这是一个加密货币纸面交易账户，交易 BTC 与 ETH 两个标的，每 5 秒重新评估一次。

BTC：现价 80313.61 USD；24h -0.87%；1h -0.08%；5m +0.12%；1m -0.03%。 当前空仓。
ETH：现价 2574.59 USD；24h -1.87%；1h -0.05%；5m +0.08%；1m +0.01%。 当前空仓。
```

问题（`questions`）：

| id | 类型 | 含义 |
|---|---|---|
| `BTC` / `ETH` | choice | `buy` / `sell` / `hold`，criteria 见 `lib/jev.js` |
| `marketRisk` | boolean | 是否处于剧烈波动、不宜开新仓的状态 |

criteria 是写死的，页面底部「Jev 看到的状态 & 判别标准」里能看到原文，也可以 `GET /api/criteria` 取。

**信号要变成实际成交，还要过三道闸**（都在前端，可调）：

1. 概率 ≥ 阈值（默认 0.55）
2. 同标的冷却（默认 60 秒）
3. 风控开关：`marketRisk` ≥ 0.5 时强制不买

## 已知限制

| 项 | 说明 |
|---|---|
| **决策历史不跨设备** | 存在 localStorage，换浏览器就没了 |
| **服务端历史会丢** | `recent` 字段依赖 lambda 实例存活，冷启动清空；权威记录只在前端 |
| **冷启动没有短周期动量** | 5m / 1m 涨跌幅靠实例内累积的价格序列，刚启动是「未知」，Jev 会被告知以 24h / 1h 为准 |
| **行情源有免费额度** | CoinGecko 免 key 但有速率限制；拿不到时退回 Coinbase（只有现货价，无 24h 涨跌） |
| **Binance 不能用** | 美国 IP（含 Vercel us-east）返回 `451 Service unavailable from a restricted location`，已实测确认 |
| **上游会超时** | 实测约 2/40 概率出现超时或 504，前端会跳过该拍并在下一拍重试，价格不断线 |
| **信号没有预测力验证** | 最重要的一条，见开头 |
